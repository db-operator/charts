## Commit & PR Conventions for OpenCode Agents

The following guidelines apply to all commits and PRs created by or by using OpenCode agents:

1. **Single Branch per Feature** – Always create a dedicated topic branch (e.g., `feature/x`) and commit a minimal, self‑contained change set.
2. **Clear Commit Message** – The commit subject must be a concise summary. Append a trailing note, **always** mentioning the AI model used: `Generated by AI (model: gpt-oss:20b)`.
3. **PR Title & Body** – The PR title should mirror the commit message. The body must state that the PR was automatically generated by an AI, and identify the model.
4. **Author Identity** – Use the bot’s configured Git email/address when committing. If a different identity is required, set `--author` accordingly.
5. **No Hidden Rewrites** – Avoid auto‑squashing or rewriting commits that have already been pushed unless a user explicitly requests it.
6. **Semantic Versioning** – When touching release‑related code, include a semantic patch note.
7. **Fast, Idempotent Commits** – Commit messages should not include build or long execution steps.
8. **Documentation** – Add inline comments if the change is complex. The PR body can reference the relevant `Taskfile` or script changes.

Follow these rules to maintain a predictable, transparent artifact trail for all AGENT‑generated work.
